# Shadows Cast by Migration

When the Apollo program's guidance computer received its famous "1202" alarm during the Eagle's descent, it wasn't a bug in the new code—it was an interaction between the legacy rendezvous radar system and the newer landing routines. Both worked perfectly in isolation. Together, they contested for the same interrupt cycles. Margaret Hamilton's team had anticipated this kind of failure mode, building in restarts that preserved critical state while shedding lower-priority tasks.

Software migrations cast similar shadows. When Field Theory evolved from single-directory command storage to a multi-directory watcher system, the new `addWatchedDir` mechanism correctly populated the commands index. But `detectCommands` still guarded its logic with a check against the legacy `directoryPath` field—a field that the new system never touched. The commands were there, catalogued and ready, but the detection logic couldn't see them. Like Apollo's radar and landing computer, each subsystem was correct in its own context. The bug lived in the seam between two eras of the same codebase, invisible until a voice spoke the words "use the commit command" and nothing happened. Migration completes not when new code ships, but when the last assumption from the old world stops haunting the new.
