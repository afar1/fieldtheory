# State Accumulation and Defensive Timeouts

The window-close bug reveals a pattern common in distributed systems: defensive mechanisms that become offensive when stacked. The grace period timeout was added to protect against a specific race condition (dock.hide triggering blur), but once that race was eliminated by a different fix, the defensive code became dead weight—worse, it became an obstacle. Each collapse action was refreshing the grace period timestamp, and if the user collapsed multiple times in quick succession, the grace periods would overlap, creating an ever-extending window where blur events were ignored.

This is reminiscent of the TCP "silly window syndrome" discovered in the early 1980s, where well-intentioned flow control mechanisms interacted to create pathological behavior. The sender and receiver were each being "polite," waiting for the other, resulting in tiny inefficient packets. The fix wasn't to add more logic—it was to recognize that two defensive mechanisms were fighting each other and remove one. Similarly here: the grace period was defending against a dock transition that no longer happens. Removing it doesn't just fix the bug; it makes the system simpler and more predictable.
