# Supabase integration (mobile + Electron)

### Goals

- **Save current device state** to Supabase (seed an account) and let each user do the same.
- **DB + infra** for transcripts, tasks, observations with per-user RLS.
- **Companion Mac app (Electron)** can query the same data using the Supabase JS client.

### Guiding principles (kept simple on purpose)

- **Single source of truth**: Supabase is the source; device is a cache.
- **Minimal auth**: Email OTP (no deep links) to start; can add magic-link later.
- **One well-named sync function**: push local → remote, pull remote → local, dedupe by `client_id`.
- **Safe by default**: RLS on all tables; anon key in client; no server needed.
- **No over-engineering**: No background sync, no websockets, no fancy merge strategy. Last-write-wins.

### Phase 0 — Setup (10–15 min)

1. Create a Supabase project. Get `SUPABASE_URL` and `SUPABASE_ANON_KEY`.
2. Add `.env` with those keys; use existing `babel-plugin-inline-dotenv` (already in devDeps).
3. Confirm email auth is enabled in Supabase Auth (default) and OTP emails are allowed.

### Phase 1 — Schema + RLS (SQL in Supabase SQL editor) (20–30 min)

- Create tables with per-user rows, dedupe and sort columns, and timestamps.
- Enable RLS and add straightforward owner policies.
- Create a profile on first sign-in.

SQL (run in order):

```sql
-- required for gen_random_uuid(); on newer projects use uuid_generate_v4() if preferred
create extension if not exists pgcrypto;

-- profiles mirrors auth.users (owner-only)
create table if not exists public.profiles (
  id uuid primary key references auth.users (id) on delete cascade,
  email text,
  created_at timestamptz not null default now()
);

-- shared columns helper
-- client_id: stable id from device (your current string id)
-- client_created_at_ms: epoch ms captured on device for exact ordering
-- updated_at: server-side, for simple conflict resolution
create table if not exists public.todos (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users (id) on delete cascade,
  text text not null,
  completed boolean not null default false,
  client_id text unique not null,
  client_created_at_ms bigint not null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table if not exists public.observations (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users (id) on delete cascade,
  text text not null,
  client_id text unique not null,
  client_created_at_ms bigint not null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table if not exists public.transcripts (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users (id) on delete cascade,
  text text not null,
  client_id text unique not null,
  client_created_at_ms bigint not null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

-- simple updated_at trigger
create or replace function public.set_updated_at() returns trigger as $$
begin
  new.updated_at = now();
  return new;
end; $$ language plpgsql;

create trigger set_todos_updated_at before update on public.todos
for each row execute function public.set_updated_at();

create trigger set_observations_updated_at before update on public.observations
for each row execute function public.set_updated_at();

create trigger set_transcripts_updated_at before update on public.transcripts
for each row execute function public.set_updated_at();

-- RLS
alter table public.profiles enable row level security;
alter table public.todos enable row level security;
alter table public.observations enable row level security;
alter table public.transcripts enable row level security;

-- owner-only policies
create policy "profiles owner" on public.profiles
  for select using (auth.uid() = id);

create policy "todos owner" on public.todos
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);

create policy "observations owner" on public.observations
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);

create policy "transcripts owner" on public.transcripts
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);

-- create profile row on new user
create or replace function public.handle_new_user() returns trigger as $$
begin
  insert into public.profiles (id, email) values (new.id, new.email);
  return new;
end; $$ language plpgsql security definer;

drop trigger if exists on_auth_user_created on auth.users;
create trigger on_auth_user_created
  after insert on auth.users
  for each row execute function public.handle_new_user();
```

### Phase 2 — Mobile app: auth + client + sync (60–90 min)

- Add deps: `@supabase/supabase-js@^2`, `react-native-url-polyfill`, `react-native-get-random-values`.
- New files:
  - `services/supabase.ts`: create client from env.
  - `services/auth.ts`: `requestOtp(email)`, `verifyOtp(email, token)`, `getSession()`, `signOut()`.
  - `services/sync.ts`: `syncUp()` and `syncDown()` that map local `Todo/Observation/TranscriptEntry` to remote rows with `client_id = local.id` and `client_created_at_ms = local.createdAt`.
- UI edits in `App.tsx` settings modal: add Sign In/Out + Sync Now buttons (keep it boring and small).

- Sync behavior:
  - `syncUp`: For each local item, `insert ... on conflict (client_id) do update` to ensure dedupe; set `user_id = session.user.id`.
  - `syncDown`: Pull all rows for the user; merge by `client_id` into AsyncStorage. Last-write-wins by comparing `updated_at` vs local last-known; if equal or unsure, keep remote.
  - Show one simple “Synced at HH:MM” notice.

### Phase 3 — Electron companion app (60–90 min)

- Create `mac-app/` (Electron + Vite + TS).
- Use `@supabase/supabase-js` and the same OTP flow (email + 6-digit code).
- Views: sign-in screen, read-only lists of transcripts, todos, observations; a “Refresh” button.
- Optional: export to CSV.

### Phase 4 — Nice-to-haves (later)

- True magic links (deep linking) for mobile.
- Incremental sync using `updated_at > last_sync_at` checkpoints.
- Soft deletes (add `deleted_at`) if we need undo/restore.

### What we are explicitly NOT doing (to stay simple)

- No backend server, Edge Functions, or complex sync engine.
- No background sync or subscriptions.
- No shared teams or cross-user data yet.
